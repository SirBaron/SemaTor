SemaTor release history

1.1.579 — Turrican II GPU Smooth Motion and lighter picture preparation

  • Turrican II on the GPU: Smooth Motion now uses indexed Vulkan composition in Original, Fit and wider views, including Amiga artwork, native sprite masks, scanline colours and environmental effects. Layers are prepared once per game interval and reused for its display-rate pictures. The GPU route takes priority over the older Auto/Processor preference. CPU replay remains the fallback for an unavailable compatible renderer or a rejected scene check.
  • Picture processing on the GPU: Colour processing, comparison view and Super ST 2x/3x/4x work with the new renderer. Ordinary display-rate Smooth Motion stays on the GPU through these stages. Original 50 Hz pictures with frame generation and explicit diagnostic captures retain their required readback paths.
  • Less repeated CPU work: Shared native-screen decoding reuses unchanged bitplanes and palettes. Enhanced pictures avoid duplicate uploads, snapshots copy changed RAM blocks into their owned buffers, and common CPU timing calculations do less work. These changes apply on desktop and Android while preserving emulated timing and game behaviour.
  • Turrican II threaded rendering: Smooth Motion and Fit compose from owned snapshots beside the running emulation. Camera, artwork and reset state stay with the selected snapshot; loading a state or starting another game invalidates retained drawing data.
  • Sound reliability: Native output cannot replay an already consumed audio range after a delayed flush. State loads clear old resampler/fade history, paused time no longer biases the producer-rate estimate, and device-status publication avoids racing an output reopen. Native/SDL labels report the actual backend. Existing ST gain, filters and stereo mixing are preserved.
  • Input and save requests: One-shot requests are consumed atomically, and Save/Load keeps the slot selected when the action was pressed. Input-ring overflow reconciles held controls so a dropped release cannot leave a key or button stuck.
  • Phone test: saves and menus: Visible landscape Save/Load actions open the correct slot page. Settings use Display, Picture, Sound, Controls, Game options, and System & diagnostics, with advanced choices inside. Choice previews avoid temporary settings writes; touch focus, scrolling, navigation and diagnostics sharing receive fixes.
  • Phone test: loading and placement: The SemaTor loading screen stays correctly sized during game-launch preparation. Fast-core controls cover registered game threads, performance updates run on the UI owner, top controls follow rotation, and Turrican fire presets no longer send an extra mouse click.
  • More useful diagnostics: GPU picture counts report completed composition, captures record the actual GPU image, and native shortages are counted even when resampler lookahead remains queued. A status-indicator bug that could draw into an offscreen image is fixed.

Windows x64, Linux x86-64 and Linux ARM64 public builds and signed updates. Android remains a private phone-test APK; it is not included in the public release. Further game-specific GPU conversions follow separately.

1.1.578 — Threaded runtime, one frame rate setting and native sound

  • One frame rate: the frame cap, the Smooth Motion rate and the motion rate are now one Frame rate for all games (F12 > Display and SemaOS Video settings): Match display (the new default: one picture for every refresh of your screen - 144 a second on a 144 Hz screen), 60, 120, 144 or 240, or any of the old caps under Tools > Frame rate (advanced). Smooth Motion’s in-between pictures, the Fire & Ice, Buggy Boy and Wizball motion and frame generation all fill exactly these pictures; the game’s own speed never changes.
  • Your settings carry over: a frame cap you chose is kept as the frame rate. The old default of 60 becomes Match display (pick 60 again if you want it). A Smooth Motion rate of 60-240 under the default cap becomes the frame rate, and 50 Hz exact pictures stay available under Tools > Frame rate (advanced) > Smooth Motion pictures. Older SemaTor versions can still read the settings.
  • Sync to display and Variable refresh: Sync to display (new, on by default) makes games wait for the screen before each picture, so there is no tearing on a fixed-refresh screen; off shows each picture at once for the lowest delay. One Variable refresh screen setting (Auto, Yes for VRR, G-SYNC and FreeSync, or No for a fixed refresh, which Beam racing needs) replaces the two switches that could disagree. Frame generation works out its own multiplier from the frame rate and the game’s rate.
  • Fast forward speed (new): 2x, 3x, 4x, 6x (the default, as before), 8x or Max, under Machine.
  • Match display on high-refresh Windows monitors: Windows now reads the display’s real refresh rate, so Match display uses the full rate on monitors that were reported as 60 Hz.
  • Threaded runtime (new, on by default): the emulation and its sound run on their own thread, and the pictures are composed alongside from a snapshot of each game tick, so a slow display or a busy menu no longer holds the game back. The game itself, its timing and its sound are exactly the same as before. Runtime: Threaded or Classic under F12 > Debug; it applies when the next game starts. Nine enhanced games compose their pictures without ever holding the game: Xenon, Xenon 2, Zynaps, Toki, Turrican, Strider, Rick Dangerous II, Buggy Boy and Wizball.
  • Steadier Smooth Motion: Smooth Motion steps down only when game ticks really run late (it mistook frame-locked games such as Xenon for an emulation falling behind), and its in-between pictures follow the rate the screen is really shown at. A new Smooth Motion drawing setting picks Auto (the default), Processor or Graphics card for games that can draw their in-between pictures either way.
  • Native sound output: sound now goes straight to Windows (WASAPI) and follows a change of the default sound device, with SDL as a fallback (Sound output: Native or SDL). The sound engine also gained fixes: a bug that ran the sound 1% slow, recovery after a stall, and a resampler that dulled the high notes.
  • Auto HDR for every picture mode: Auto HDR (ordinary pictures given HDR highlights) is now its own setting with its own strength, for Sharp pixels, Simple filters and the CRT cabinet alike. It needs an HDR display; on SDR the setting says so and nothing changes.
  • Vertical modes: Simple filters and the CRT cabinet now work in the Xenon and Xenon 2 vertical modes, and Xenon 2’s vertical mode is steadier.
  • New SemaOS start-up: one animated SemaOS start-up instead of two, with the work done alongside it, so the desktop is ready sooner.
  • Game fixes: Xenon’s stall at the start of a level is split up so the picture keeps moving; Buggy Boy, Zynaps and Toki cost less to run.
  • Diagnostics: Save diagnostics (F12 > Debug > Performance & diagnostics) writes one text file with the device, graphics and settings, the last two minutes of play and the end of the log, to attach to a problem report. The diagnostics also show SemaTor’s GPU usage.
  • Reliability: many fixes found in a code review and a long verification pass, among them game sessions that now start clean after returning to the library.

Windows x64, Linux x86-64 and Linux ARM64 public builds and signed updates. The Android phone build remains in private testing; it is not a public Android or Play Store release.

1.1.576 — Vertical modes, Smooth Motion at any refresh rate, FidelityFX, sturdier sound and Linux ARM64

  • Smooth Motion at any refresh rate: every Smooth Motion game now draws its in-between pictures for the moment each display refresh is shown, at 60, 90, 120, 144, 240 Hz and in between, without changing game speed, timing or sound. A new per-game "Smooth motion rate" row offers Match display (default), 60, 120, 144, 240 Hz or the previous 50 Hz exact pictures. Heavy scenes step down gracefully instead of stuttering, and frame generation no longer interpolates on top.
  • Vertical modes (experimental): Xenon and Xenon 2 can fill a tall window or a monitor turned upright. The original view sits slightly above the bottom by default, with the stretch already flown below and what is coming above; choose Bottom, 10%, 15%, 20% or Middle under "Original view position". Xenon 2 shows upcoming formations flying in, every member on its own way with its own animation, and the wall enemies animate in the extra rows. A "Shot range" option lets shots travel their original distance beyond the 4:3 view. Both games stay vertical from the title and attract flyby to game over. Restart after changing the option.
  • FidelityFX Optical Flow: a new experimental frame generation method using AMD’s open-source FidelityFX optical flow on any Vulkan GPU (AMD, Intel or NVIDIA). NVIDIA Optical Flow is unchanged.
  • Sturdier sound: the sound queue is kept steady with tiny rate corrections instead of pausing and refilling, absorbs brief stalls, follows headphones or Bluetooth devices being plugged in or removed, and reliably comes back after the window regains focus.
  • Presentation thread: on Vulkan, waiting for the display and submitting frames now happen on their own thread, so the game and its sound keep a steady pace while the display catches up. F12 > Debug > Performance & diagnostics can switch it off.
  • Smoother interface: save-slot previews, SemaOS thumbnails and Continue cards load in the background, menu and library uploads are smaller, and the Jukebox scope and desktop music visualiser cost much less while looking the same.
  • Widescreen: pausing a widescreen game keeps the widescreen picture, and the Zynaps title colour bars now run across the full width. A raster timing fix removes a faint colour flicker above Zynaps’ panel; colour changes written just after a line’s last pixel now count from the next line, as on the ST.
  • SemaOS and menus: GEM windows look more like real GEM dialogs, the Jukebox has icon playback buttons and a sidebar that scrolls in small windows, and the F11/F12 menus fit small windows better.
  • Linux ARM64 (new): a native Linux ARM64 build for Arm Linux devices such as Valve’s Steam Frame, with its own signed updates. It has been tested under emulation; real Arm hardware reports are welcome.

Windows x64, Linux x86-64 and Linux ARM64 public builds and signed updates. Android remains a separate test preview; it is not a public Android or Play Store release.
